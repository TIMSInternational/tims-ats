# Wave 2.5 Slice 3 — Scope Enforcement: Recruitment — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development

> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the recruitment data layer actually enforce `ctx.access.scope` — a
central per-entity policy registry (`scopeWhereFor`) + ownership probe
(`assertScoped`) wired into every vacancy/candidate/pipeline/interview/offer/
assessment read and by-id mutation, plus the slice-1 codex carry-over
(submitScorecard evaluator-ownership).

**Architecture:** Routers compute the scope fragment once per request via
`scopeWhereFor(entity, ctx.access, ctx.user.id)` (async — anchors) and compose
`where: { AND: [ {organizationId, ...}, scopeFragment, inputFilters ] }` — NEVER
object spread (CI check 13 enforces). Services/repos receive the fragment as a
plain `scopeWhere` param and compose it inside their own AND (services stay free
of tRPC/access imports). By-id mutations call `assertScoped(entity, id, …)` (or
add the fragment to their existing org-probe `findFirst`). **Behavior-neutrality
invariant: `organization` (and `company`) scope → `{}` fragment** — all prod
grants today are legacy `'all'`→organization, so merging this slice (which
auto-deploys) changes NOTHING until `seed-access.ts --apply` runs at wave-data
deploy. Spec: `docs/WAVE-2.5-ACCESS-CONTROL.md` (entity-policies row + slice 3).

**Tech Stack:** TypeScript strict, tRPC v11, Prisma 6 via `tenantDb`, Vitest
(behavior tests w/ mocked `@tims/db` for the access layer; static AND-composition
tripwires per module, house style).

**Baseline (verified at branch creation):** 298 tests / 42 files green on
`feat/access-scope-recruitment` off main `cec0fdc` (slices 1+2 merged AND live in
prod; auto-deploy works — every merge deploys; pre-seed prod has only
org-equivalent grants, so neutrality is the deploy-safety property).

**Recon ground truth (verified Jun 12, do not re-litigate):**
- All ~70 recruitment procedures already run under the correct
  `permissionProcedure(module, action)` (verified per file). The gap is the DATA
  layer: every query filters only by `organizationId`.
- Anchor fields: `Vacancy{teamId?, businessUnitId?, assignedTo?, createdBy}`;
  `Interview{vacancyId, evaluators: InterviewEvaluator[{interviewId,userId}]}`;
  `Offer{vacancyId, candidateId}`; `AssessmentAssignment{vacancyId, candidateId}`;
  `Application{vacancyId, candidateId}` (model in `pipeline.prisma`);
  `Candidate` has NO direct anchor — scopes via `applications.some.vacancy`.
- `AnchorLoader` (packages/api/src/access/anchors.ts) exposes `teamMemberIds()`
  (floors to `[self]`), `unitIds()`, `panelInterviewIds()`. It does NOT expose
  the led-team ids that Vacancy team-scope needs → Task 1 adds `ledTeamIds()`
  (floor `[]`, fail-narrow).
- `AccessContext = { allowed: true, scope, roles, anchors: AnchorLoader | null }`
  injected by `requirePermission` (packages/api/src/trpc.ts). `anchors` is null
  only for org-less users, who cannot reach tenant routers (BAD_REQUEST in
  build.ts) — policies still fail closed if null.
- Service call pattern: `candidateService.list(ctx.user.organizationId, input)`,
  `pipelineService.getBoard(orgId, vacancyId, status)` → these gain a
  `scopeWhere` param computed in the router.
- `submitScorecard` (packages/api/src/routers/interview/scorecards.ts:33) probes
  org only, then upserts with `evaluatorId: ctx.user.id` — ANY org member can
  submit a scorecard for any interview. Carry-over fix: require an
  `InterviewEvaluator` row (FORBIDDEN otherwise).
- Routers import `tenantDb as db`; repos/services use `tenantDb` via repositories.
- Seeded-matrix scopes that activate post-seed: leader = team (vacancy read+
  approve, pipeline read/update, interview read/create/update, offer read+
  approve); committee = team-scoped interview read/update (panel-anchored);
  hrbp = unit (read-only across all six). recruiter/hr_admin/super_admin = org →
  `{}` fragment (today's behavior).
- OUT of slice scope (recorded in Task 10): `recruitment-analytics` router
  (separate module, org-level aggregates), assessment QUESTION BANK endpoints
  (org-level authoring, no vacancy anchor — stays org), `company` scope (no
  grants use it; treated as organization).

```typescript
import { TRPCError } from '@trpc/server';
import type { AccessContext } from './index';

// Wave 2.5 slice 3 — per-entity scope policy registry (design doc F3). The ONE
// place that knows each recruitment entity's anchor relations. Routers compose
// the returned fragment as AND: [{organizationId...}, fragment, inputFilters] —
// NEVER object spread (CI check 13). organization/company → {} is the
// deploy-safety invariant: pre-seed prod grants are all org-equivalent, so this
// slice is behavior-neutral until seed-access --apply runs.
export type ScopedEntity =
  | 'vacancy'
  | 'candidate'
  | 'application'
  | 'interview'
  | 'offer'
  | 'assessmentAssignment';

type Fragment = Record<string, unknown>;

const ENTITIES: ReadonlySet<string> = new Set([
  'vacancy', 'candidate', 'application', 'interview', 'offer', 'assessmentAssignment',
]);

export async function scopeWhereFor(
  entity: ScopedEntity,
  access: AccessContext,
  userId: string,
): Promise<Fragment> {
  if (!ENTITIES.has(entity)) {
    throw new TRPCError({ code: 'INTERNAL_SERVER_ERROR', message: `Entidad sin politica de alcance: ${entity}` });
  }
  const { scope, anchors } = access;

  if (scope === 'organization' || scope === 'company') return {};

  if (scope !== 'own' && scope !== 'team' && scope !== 'unit') {
    throw new TRPCError({ code: 'INTERNAL_SERVER_ERROR', message: `Alcance desconocido: ${String(scope)}` });
  }
  if (!anchors) {
    // Narrow scope but no anchor loader (org-less user) — fail closed, never unscoped.
    throw new TRPCError({ code: 'FORBIDDEN', message: 'Sin contexto de organizacion para alcance restringido' });
  }

  const vacancyFragment: Fragment =
    scope === 'team'
      ? { OR: [{ teamId: { in: await anchors.ledTeamIds() } }, { assignedTo: userId }] }
      : scope === 'unit'
        ? { businessUnitId: { in: await anchors.unitIds() } }
        : { OR: [{ assignedTo: userId }, { createdBy: userId }] }; // own

  switch (entity) {
    case 'vacancy':
      return vacancyFragment;
    case 'candidate':
      // No direct anchor on Candidate — visibility flows from the vacancies the
      // user can see, via that candidate's applications.
      return { applications: { some: { vacancy: vacancyFragment } } };
    case 'interview':
      // Panel arm: an assigned evaluator (committee) sees their interviews
      // regardless of team; a leader sees team-vacancy interviews (design gap #5).
      return scope === 'own'
        ? { evaluators: { some: { userId } } }
        : { OR: [{ vacancy: vacancyFragment }, { evaluators: { some: { userId } } }] };
    case 'application':
    case 'offer':
    case 'assessmentAssignment':
      return { vacancy: vacancyFragment };
  }
}
```

```typescript
import { TRPCError } from '@trpc/server';
import { tenantDb } from '@tims/db';
import { scopeWhereFor } from './entity-policies';
import type { ScopedEntity } from './entity-policies';
import type { AccessContext } from './index';

// Ownership probe for by-id mutations (design invariant #3): a narrow-scoped
// user must not reach an out-of-scope row by id-guessing. NOT_FOUND (not
// FORBIDDEN) so the response doesn't confirm the id exists.
const DELEGATES = {
  vacancy: () => tenantDb.vacancy,
  candidate: () => tenantDb.candidate,
  application: () => tenantDb.application,
  interview: () => tenantDb.interview,
  offer: () => tenantDb.offer,
  assessmentAssignment: () => tenantDb.assessmentAssignment,
} as const;

export async function assertScoped(
  entity: ScopedEntity,
  id: string,
  access: AccessContext,
  userId: string,
  organizationId: string,
): Promise<void> {
  const fragment = await scopeWhereFor(entity, access, userId);
  const delegate = DELEGATES[entity]() as { findFirst: (args: unknown) => Promise<unknown> };
  const row = await delegate.findFirst({
    where: { AND: [{ id }, { organizationId }, fragment] },
    select: { id: true },
  });
  if (!row) {
    throw new TRPCError({ code: 'NOT_FOUND', message: 'Recurso no encontrado' });
  }
}
```
