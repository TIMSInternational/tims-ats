# Wave 2.5 Slice 5 — Role-Aware UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** The client finally consumes the access engine: per-role sidebars, real
role labels, and clean AccessDenied screens instead of broken-page+FORBIDDEN toasts.

**Architecture:** `PermissionsProvider` (client, inside AdminShell's TRPCProvider)
fetches `trpc.auth.getSessionInfo.useQuery()` ONCE → context `{ can(module,
action), roles, roleLabel, isLoading }`. A single shared `PATH_MODULE` map drives
BOTH the sidebar filter and ONE shell-level `<RouteAccessGuard>` (no per-page
edits — 45+ pages stay untouched). **Privileged bypass mirrors the API
(build.ts): `isPlatformOwner` prop OR roles ∋ super_admin/platform_owner →
`can()` always true** — without this the platform owner (no rolePermission rows)
would see an EMPTY sidebar. Candidate portal + `/platform` untouched (`/platform`
already server-gated). Pre-seed neutrality: legacy grants still differ per role
by MODULE, so sidebars differ immediately; scopes activate at the data deploy.

**Recon facts:** `auth.getSessionInfo` (packages/api/src/routers/auth.ts:21)
returns `{user, organization, roles: slugs[], permissions: {module, action,
scope}[]}` — sufficient. Sidebar nav = `useNavSections()` in
`apps/web/app/(admin)/sidebar.tsx` (static array; role label hardcoded as
`t.nav.admin` in the user chip). `AdminShell` (client) mounts TRPCProvider +
I18nProvider and receives `isPlatformOwner`. i18n = typed es/en JSON with CI
parity. House tests = static tripwires in tests/.

**Baseline:** 452 tests green, branch `feat/access-role-aware-ui` off main c2b4f9d.

skeleton (never AccessDenied during load; sidebar renders nothing for gated

fail OPEN for rendering (API is the boundary; a network blip must not blank the
app) with a console.warn. AccessDenied screen: centered card, lock icon, i18n
title/message, button → `/dashboard`. `roleLabel` = first role slug mapped via
i18n `roles.*` (platform owner → platform_owner); multiple roles → join the

recruiter, leader, committee, employee).

### Task 2: Role-aware sidebar + real role label (TDD)

**Files:** Modify `apps/web/app/(admin)/sidebar.tsx`. Append tripwires to
tests/access/role-aware-ui.test.ts.

- Each nav item gains `module: <module|null>` (SAME values as PATH_MODULE —
  import a shared `NAV_MODULES`/reuse PATH_MODULE from lib/permissions.tsx,
  do NOT duplicate the mapping).
- Filter: item renders iff `module === null || can(module, 'read')`; a SECTION
  renders iff it has ≥1 visible item. While loading: render only null-module
  items (no flash).
- Role label: replace `t.nav.admin` in the user chip with `roleLabel` from
  `usePermissions()` (fallback to `t.nav.admin` while loading/absent).
- Platform sidebar untouched.

**Tripwires:** sidebar.tsx matches `module:` ≥ 20 times OR imports the shared
map; matches `can(`; the literal `t.nav.admin` appears only as the FALLBACK
(assert `roleLabel` present); platform-sidebar.tsx unchanged
(`git diff --name-only` sanity in report, not a test).

Steps: RED → implement → GREEN → full suite + both tscs → commit
`feat(ui): role-aware sidebar + real role label (slice 5)`.
