# Wave 2.5 Slice 4 — Scope Enforcement: People — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the access engine to PEOPLE entities (user-anchored, not
vacancy-anchored) and wire every people-module router — performance (okrs/
coaching/feedback), onboarding, learning, compensation, ninebox, succession,
teamIntel — so own/team/unit grants actually filter rows. This is the LAST
slice the wave-data deploy waits on: once merged+deployed, `seed-access.ts
--apply` becomes runnable.

**Architecture:** Same playbook as slice 3 (study `git log --oneline
eef0154..2d9af1c` — implementers copy those commits' conventions). New:
`unitMemberIds()` anchor (users belonging to assigned units) and people-entity
policies in `entity-policies.ts` where the fragment anchors on the row's
EMPLOYEE-user field (`userId`/`employeeId`/`toUserId`/...) — own→`{field: me}`,
team→`{field:{in: teamMemberIds}}`, unit→`{field:{in: unitMemberIds}}` — plus
role-specific OR-arms (coach sees sessions they lead; buddy sees plans they
buddy). Org-rollup analytics endpoints get the `requireOrgScope` interim gate
(recruitment-analytics precedent) — scope-aware analytics stays a recorded
follow-up. **Deploy-neutrality invariant holds: org/company → `{}` fragments
and the org-gate is a no-op at org scope; merging auto-deploys safely
pre-seed.**

**Tech Stack:** TypeScript strict, tRPC v11, Prisma 6 via `tenantDb`, Vitest
(behavior tests for policies/anchors; static AND-composition tripwires per
module — house style).

**Baseline (verified at branch creation):** 372 tests / 51 files green on
`feat/access-scope-people` off main `2d9af1c` (slices 1-3 merged AND live in
prod; pre-seed prod grants are all org-equivalent).

`anchors.ts` — add to interface + slot + method:
```typescript
    unitMemberIds() {
      // People-entity unit scope: every user belonging to the caller's assigned
      // units — via the direct User.businessUnitId FK OR membership in a team
      // of that unit (both forms exist in the schema; union + dedupe). Floor []
      // (no units assigned → no unit rows). Request-local like every anchor.
      unitMembers ??= (async () => {
        const units = await this.unitIds();
        if (units.length === 0) return [];
        const users = await tenantDb.user.findMany({
          where: {
            organizationId,
            OR: [
              { businessUnitId: { in: units } },
              { teams: { some: { team: { businessUnitId: { in: units } } } } },
            ],
          },
          select: { id: true },
        });
        return [...new Set(users.map((u) => u.id))];
      })();
      return unitMembers;
    },
```

`org-gate.ts`:
```typescript
import { TRPCError } from '@trpc/server';
import type { AccessContext } from './types';

// Interim gate for org-rollup analytics endpoints (recruitment-analytics,
// people dashboards): the underlying queries aggregate ORG-WIDE, so narrow
// scopes must not read them until the aggregates are scope-aware (recorded
// follow-up in REMAINING-WORK). No-op at org/company scope — deploy-neutral.
export function requireOrgScope(access: AccessContext): void {
  if (access.scope !== 'organization' && access.scope !== 'company') {
    throw new TRPCError({
      code: 'FORBIDDEN',
      message: 'Disponible solo con alcance de organizacion',
    });
  }
}
```
