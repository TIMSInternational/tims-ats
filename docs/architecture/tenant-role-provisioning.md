# Tenant role provisioning

New organizations created through the .NET 10 platform API, the legacy TypeScript platform API, an organization invitation, or self-serve signup now receive all nine system-role rows and the scoped grants from `packages/db/prisma/seed-access-matrix.ts` in the organization transaction. A failed grant write rolls back the new organization. The .NET service embeds `role-grants.json`, generated with `scripts/generate-dotnet-role-grants.ts`; the parity test compares every role and grant against the TypeScript matrix.

This fixes the previous creation paths that inserted only `super_admin` with no `role_permissions`. It also makes the default `employee` invitation role available in newly created organizations. Existing organizations are unchanged by this code. Before beta onboarding, inspect the output of the existing `packages/db/prisma/seed-access.ts` dry run for those organizations. After confirming scoped RBAC is deployed, run its `--apply` mode to reconcile missing roles and grants, then invalidate the `tims:access:*` and `tims:perm:*` caches or wait for their five-minute expiry. The reconciliation deliberately removes grants outside the approved matrix, so review its dry-run diff before applying it.

Verify each beta tenant has an active `employee` role with own-scoped onboarding grants and a recruiter role with organization-scoped vacancy grants. An invitation accepted before the roleless-account fix may already have a user without a role; the invitation cannot safely restore access on replay. Verify that identity and have a tenant administrator assign the intended role explicitly.
