# Proctoring beta: implementation and acceptance contract

Status: **architecture and fail-closed admission policy only; candidate capture, evidence intake, AI and review are not live** (2026-09-28).

This plan implements Wave 1.5b from `docs/WAVE-1.5a-ASSESSMENT-PLAYER.md`. The current player records only assessment-data consent; `proctoring_sessions.events` is a Prisma JSON shell and staff can read/flag it, but no candidate media is captured or persisted. The proctoring add-on in the entitlement catalog has no usage source. The standalone .NET 10 policy at `Tims.Domain/Proctoring/ProctoringCapturePolicy.cs` is dark and cannot enable proctoring by itself.

## Beta contract and budget

- Design envelope: at most 25 simultaneous candidates, assessments at most 30 minutes, seven-day evidence target. Reject assignment of a longer assessment to a mandatory-proctoring configuration rather than silently stopping monitoring at minute 30.
- Explicit, separately versioned camera **and** screen-recording consent before starting the assessment timer. Show the exact media captured, sampling cadence, retention and human-review use. Denial leaves the assessment unstarted; give the candidate a way to contact the organization for an accessible alternative. The existing `habeas_data` assessment consent is not a substitute.
- Camera JPEG still every 20 seconds, maximum 90 frames at 128 KiB each; screen JPEG still every 60 seconds, maximum 30 frames at 256 KiB each. No continuous audio/video. This caps a 30-minute attempt at 18.75 MiB and 120 images; 25 simultaneous full attempts create at most 3,000 images / 468.75 MiB. These are admission ceilings, not a prediction of actual AWS charges.
- Browser visibility/focus, permission revocation, missing media tracks, display-surface type and reconnect gaps are timestamped **signals**, not proof of misconduct. No model or event automatically fails an assessment or rejects a candidate.

## Production path, in dependency order

1. **Owned schema and rollout switch.** Add EF-owned `proctoring_attempts`, `proctoring_consents`, `proctoring_evidence`, `proctoring_events`, `proctoring_findings` and `proctoring_reviews` with `organization_id`, assignment/candidate foreign keys, immutable consent text version/timestamp, evidence object key/hash/size/expiry, model version, reviewer identity and decision. Add each to `docs/architecture/table-ownership.md` and apply fail-closed tenant RLS. Keep the existing Prisma-owned `proctoring_sessions` untouched until its ownership flip. Add a dark-by-default `.NET` enable flag and per-org entitlement check; every unconfigured route returns unavailable. Never enable candidate capture solely because a frontend build ships.
2. **Candidate identity and consent.** In .NET 10, resolve the Supabase JWT with `PrincipalResolver` using the route org and session email. Require `PrincipalType.Candidate`, exact assignment ownership, active org, `in_progress` lifecycle, and separate consent. A staff session or same email in another tenant must fail. Atomically create a single attempt/consent before the existing start transition, so the candidate cannot lose timed minutes in browser permission dialogs. A declined, revoked or expired consent blocks new upload tickets. Do not trust client-provided candidate/org ids, counts, or timestamps.
3. **Camera/screen preflight.** Only when backend capability and org entitlement are on, the candidate player asks for `getUserMedia` and `getDisplayMedia` after an explicit click. It shows local previews and permission state; it does not upload before consent/attempt creation. A stream ending or browser navigation stops tracks and records an interruption. Require an allowed `displaySurface`; browsers cannot force the user's chooser. Show a clear recovery path for unsupported browsers and accessibility exceptions. No hidden recording.
4. **Bounded upload tickets and object verification.** Candidate requests a one-use, short-lived presigned S3 upload for an enumerated camera/screen JPEG. The .NET intake uses `ProctoringCapturePolicy` after tenant-scoped reads under a row lock, reserves the next sequence/count, and returns a key scoped by tenant/attempt plus exact content type, maximum bytes and hash requirement. The browser uploads **directly** to a private AWS S3 evidence bucket; API and Vercel never proxy image bytes. S3 CORS is restricted to approved origins, public access is blocked and objects use server-side encryption. A completion call performs `HeadObject` and verifies key, size, MIME/checksum and reservation before marking evidence ready. Expired/unconfirmed reservations are cleaned without counting as verified evidence. Rate limits and quotas apply to both ticket and completion calls.
5. **Retention.** Compute `delete_after = accepted_at + 7 days` on each evidence row. A scheduled idempotent worker deletes due objects and metadata; S3 lifecycle expiration is a backstop, not an exact-time guarantee. Include failed uploads, thumbnails and derived findings in deletion. Test deletion with a short test retention setting, then check the real bucket lifecycle and IAM in the AWS account. Legal hold, export and privacy requests require a separately approved policy before launch; do not silently extend seven days.
6. **AI and human review.** An S3 completion event queues a bounded job in SQS. The first model tier runs cheap deterministic checks (frame decodability, timing, track gaps, image quality) and selective AWS Rekognition face count on sampled camera frames. A pinned, self-hosted Hugging Face model in AWS may analyze *uncertain* frames after its license, provenance, bias and accuracy are approved; avoid shipping raw candidate media to an external hosted inference endpoint. Store model ID/version, confidence, frame IDs and reason codes. Staff review is tenant-scoped with expiring object-view URLs and an explicit reviewer decision; AI findings are advisory. Critical signals may raise a staff notification, never an automatic rejection.
7. **Metering and cost guard.** Count one completed, consented attempt for the `proctoring` entitlement; reconcile retries by attempt ID. Emit S3 request/storage, SQS, Rekognition and inference counts to a daily per-org budget. The worker must stop optional inference when a budget is exhausted while preserving the assessment and review path. For a 25-person / 30-minute load test the admission ceiling is 3,000 objects; the number of model calls is an independently configured budget and must be measured, not inferred from frames.

## Acceptance and release gates

| Gate | Testable result |
| --- | --- |
| Dark deploy | New .NET endpoints are unavailable when feature flag or org entitlement is off; no browser permission prompt or upload occurs. |
| Consent and identity | Fresh consent is required; old data-processing consent alone fails; a foreign candidate, staff token, expired assignment and cross-org email all fail without exposing assignment existence. |
| Capture | Camera or screen denied, revoked, unsupported, interrupted and resumed produce accurate candidate messaging and bounded interruption events. Candidate can finish a non-proctored assessment without proctoring enabled. |
| Intake | Wrong MIME, empty/oversized bytes, forged count/time, replayed ticket, stale reservation, parallel quota race and mismatched S3 checksum fail closed. No object is readable publicly. |
| Retention | Seven-day due rows/objects/derivatives disappear, including orphaned uploads; deletion failures retry and alert. |
| AI | Version-pinned eval set contains single/multiple/no face, poor light, occlusion, differing skin tones, screen-sharing modes and benign interruptions. Record precision/recall and false-positive rate with a human-reviewed threshold before enabling any finding. No automated adverse decision. |
| Operations | Load-test 25 simultaneous 30-minute attempts, assess p95 ticket/completion latency, worker backlog, dropped frames, AWS spend and review throughput. Verify AWS credentials, bucket policy/lifecycle, SQS DLQ, alerting and roll-back switch in the deployed account. |

Until these gates pass on an authenticated environment, report proctoring as **not implemented / unavailable**, regardless of the existing `proctoring_sessions` shell or passing .NET unit tests.
