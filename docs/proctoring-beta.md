# Proctoring beta: current contract and release gate

The proctoring feature is an opt-in, advisory workflow for candidate assessments. It does not verify identity, prove misconduct, or decide employment outcomes. Human reviewers must consider the assessment, device/network context, and the candidate's explanation. See the [AWS AI target architecture](architecture/2026-09-24-proctoring-ai-target.md) for the design, cost envelope, and remaining verification.

## Candidate flow

1. A super admin or tenant-bound platform owner enables proctoring for a timed assessment type in an entitled organization. The assignment snapshots this choice. An authorized, audited accommodation can remove monitoring before an assignment starts.
2. The candidate accepts assessment and camera/screen monitoring notices, supplies a live camera track, and shares the entire display. The MediaPipe face positioning hint is optional and stays on device; its face count no longer gates entry or creates a misconduct event.
3. The .NET 10 API records consent, starts or resumes one session, and retains the original timer. Browser tab/focus and track-loss signals are unverified observations. A 30-second heartbeat lets the server infer a gap after 90 seconds.
4. For an explicitly timed 1–30 minute assessment, a separate image-storage opt-in may enable sampled camera and entire-screen stills. The browser uses short-lived signed POST grants to private S3 staging objects. .NET validates and seals each image, then optionally queues camera inference. The server enforces per-session capture bounds and an organization/day admission quota. Candidate image capture can be stopped for the rest of the session; the stop is persisted by .NET, and future image intents are denied. Browser signal monitoring continues.
5. Assessment answers still submit through the existing TypeScript service, followed by .NET proctoring completion. Lost completion calls are reconciled from committed assignment state. This is a separately retried boundary, not one transaction.
6. After completion, the candidate may submit one immutable statement within seven days and before review; retrying the same submission is safe. Authorized HR admins/HRBPs may inspect scoped, audited events, sampled media, and the statement. Only super admins and tenant-bound platform owners may record a `clear`, `concern`, or `inconclusive` review. The review save checks which statement the reviewer saw and requires a refresh if it changed. No browser signal or model observation automatically fails an assessment.

Media, inference, and infrastructure are **implemented locally but disabled in production** pending staging and beta verification. Cloud inference uses Rekognition `DetectFaces` as a baseline; the pinned Hugging Face object detector is off by default until a TIMS-specific labeled evaluation. A model or queue failure must appear as unavailable analysis, never as a clean result. Candidate media requests use candidate-scoped rate limits so a company NAT does not share one anonymous bucket. Turning off cloud inference stops new admission while the pinned worker drains already-confirmed messages; the worker and queues must remain provisioned until the outbox and queues are empty. Reviewer media reads use audited links valid for at most 55 seconds and are denied after seven days. A five-minute retention sweep removes due S3 objects, with S3 lifecycle as an asynchronous backstop. Physical deletion lag must be measured.

## Verification and release gate

The local suite covers candidate authorization, consent, stop/retry, duration and quota, tenant RLS, signed upload/sealing, bounded inference contracts, idempotent results, reviewer scope, and retention transitions. It does **not** establish real-world model accuracy or AWS connectivity. Before any external beta, apply and test the migration in staging; verify signed S3 POST/CORS/CSP/KMS, SQS/Lambda retries and DLQs, real deletion, and a full candidate-to-reviewer flow on actual browsers/devices. Run the 25-candidate, 30-minute load and cost trial and record false alerts per clean assessment on consented labeled examples. Approve the exact candidate notice, seven-day media policy, non-media retention, accessibility accommodation, and reviewer escalation SLA. Keep the feature flags off until those checks pass.

The local platform-owner data-subject export covers bounded consent, session, event, evidence, finding, and candidate-statement records with fail-closed per-record audits. It excludes image bytes and storage keys and marks physical media or a truncated export for manual fulfillment. A separate, approved, audited process for physical media disclosure and erasure is still needed. The local .NET alert sweep writes scoped HR inbox notifications for heartbeat gaps and stopped tracks within a 120-second target under normal database availability; delivery still needs an AWS staging and real-device trial. The older screen-share check proves only that an entire-display track is live; it cannot attest to the physical screen or detect a second device.
