# Sprint 1.1.f — HirePrediction Snapshot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At hire time (`offer.convertToEmployee`), write one immutable `HirePrediction` row snapshotting the candidate's current FIT prediction (or recording its absence), so a future Quality-of-Hire Analyst can compare predicted fit to actual performance.

**Architecture:** New `hire_predictions` table (org-scoped, RLS, scalar FK columns + DB constraints, no Prisma relations). A pure builder maps a FitScore-or-null → snapshot; a repository persists it via the caller's transaction client; a service orchestrates read+build+write; the write is added as a single call inside the existing `convertToEmployee` `$transaction`. Instrumentation only — no analyst UI/query.

**Tech Stack:** Next.js 15, tRPC, Prisma (PostgreSQL/Supabase), TypeScript strict, Vitest.

**Spec:** `docs/superpowers/specs/2026-07-13-sprint-1.1.f-hire-prediction-design.md`

## Global Constraints

- **Clean architecture:** Router → Service → Repository. Only repositories import `db`/`tenantDb`. (The one exception: `offer/lifecycle.ts` already imports `tenantDb` directly — a pre-existing violation we are NOT refactoring this sprint. Do not add new `db` imports to routers; the new call goes router → service.)
- **TypeScript strict, no `any`.** Use `unknown` + narrow.
- **Always Prisma `select`** on reads/writes returning rows.
- **Every org-scoped table:** `organization_id` + `@@index([organizationId])` + fail-closed `tenant_isolation` RLS policy **in the same migration**.
- **`prediction_status` is a Prisma enum** `HirePredictionStatus { scored, partial, none }` (per `.claude/rules/db.md` "Prisma enums for all status/type fields" — a refinement from the spec's `TEXT`).
- **Nullable Prisma `Json` fields:** pass `Prisma.DbNull` for SQL NULL — NEVER plain `null` (plain `null` fails to type-check on `Json?` create input). Nullable scalar fields (Float/Boolean/DateTime/uuid) accept plain `null`.
- **Tests are mock/dmmf-based** — never open a live DB (CI has no postgres service). Tests live under root `tests/**`.
- **Local gate every task:** `cd packages/db && npx prisma generate --schema=prisma/schema` → `pnpm --filter @tims/api exec tsc --noEmit` → `cd apps/web && npx tsc --noEmit` → `npx vitest run` (from repo root, FULL suite — not just the new file). Run BOTH tsc and vitest every task (Vitest's transpiler accepts code that does not type-check).
- **No new user-facing strings** → no i18n keys. Do not touch `apps/web` except nothing (this sprint touches no UI).

```prisma
/// Immutable snapshot of a candidate's FIT prediction captured at hire time
/// (offer.convertToEmployee). Instrumentation for the Quality-of-Hire Analyst.
/// Scalar FK columns + DB-level FK constraints (see migration) — no Prisma
/// relations declared (nothing navigates them yet; YAGNI).
enum HirePredictionStatus {
  scored
  partial
  none
}

model HirePrediction {
  id             String @id @default(uuid()) @db.Uuid
  organizationId String @map("organization_id") @db.Uuid

  userId        String  @map("user_id") @db.Uuid
  candidateId   String  @map("candidate_id") @db.Uuid
  vacancyId     String  @map("vacancy_id") @db.Uuid
  offerId       String  @unique @map("offer_id") @db.Uuid
  applicationId String? @map("application_id") @db.Uuid

  overallScore     Float?               @map("overall_score")
  breakdown        Json?
  weights          Json?
  isPartial        Boolean?             @map("is_partial")
```

```ts
import { Prisma } from '@tims/db';

/** Plain, Prisma-free snapshot produced by the pure builder in the service layer. */
export interface HirePredictionSnapshot {
  organizationId: string;
  userId: string;
  candidateId: string;
  vacancyId: string;
  offerId: string;
  applicationId: string | null;
  overallScore: number | null;
  breakdown: unknown | null;
  weights: unknown | null;
  isPartial: boolean | null;
  fitCalculatedAt: Date | null;
  predictionStatus: 'scored' | 'partial' | 'none';
  hiredById: string;
}

export const hirePredictionRepository = {
  /**
   * Persist an immutable HirePrediction inside the caller's transaction.
   * Nullable Json columns require Prisma.DbNull (plain null does not type-check).
   */
  async createHirePrediction(tx: Prisma.TransactionClient, snapshot: HirePredictionSnapshot) {
    return tx.hirePrediction.create({
      data: {
        organizationId: snapshot.organizationId,
        userId: snapshot.userId,
        candidateId: snapshot.candidateId,
        vacancyId: snapshot.vacancyId,
        offerId: snapshot.offerId,
        applicationId: snapshot.applicationId,
        overallScore: snapshot.overallScore,
        breakdown: snapshot.breakdown === null ? Prisma.DbNull : (snapshot.breakdown as Prisma.InputJsonValue),
        weights: snapshot.weights === null ? Prisma.DbNull : (snapshot.weights as Prisma.InputJsonValue),
        isPartial: snapshot.isPartial,
        fitCalculatedAt: snapshot.fitCalculatedAt,
        predictionStatus: snapshot.predictionStatus,
        hiredById: snapshot.hiredById,
      },
      select: { id: true },
    });
  },
};
```

Create `packages/api/src/services/hire-prediction.service.ts`:

```ts
import type { Prisma } from '@tims/db';
import { fitEngineRepository } from '../repositories/fit-engine.repository';
import { hirePredictionRepository, type HirePredictionSnapshot } from '../repositories/hire-prediction.repository';

/** The FitScore fields the snapshot freezes (structurally matches getFullFitScoreForSnapshot). */
export interface SnapshotFitScore {
  overallScore: number;
  breakdown: unknown;
  weights: unknown;
  isPartial: boolean;
  calculatedAt: Date;
}

export interface BuildHirePredictionInput {
  organizationId: string;
  userId: string;
  candidateId: string;
  vacancyId: string;
  offerId: string;
  applicationId: string | null;
  hiredById: string;
  fitScore: SnapshotFitScore | null;
}

/** Pure: map a FitScore (or its absence) into an immutable HirePrediction snapshot. */
export function buildHirePredictionSnapshot(input: BuildHirePredictionInput): HirePredictionSnapshot {
  const fs = input.fitScore;
  const predictionStatus: HirePredictionSnapshot['predictionStatus'] =
    fs === null ? 'none' : fs.isPartial ? 'partial' : 'scored';
  return {
    organizationId: input.organizationId,
    userId: input.userId,
    candidateId: input.candidateId,
    vacancyId: input.vacancyId,
    offerId: input.offerId,
    applicationId: input.applicationId,
    overallScore: fs ? fs.overallScore : null,
    breakdown: fs ? fs.breakdown : null,
    weights: fs ? fs.weights : null,
    isPartial: fs ? fs.isPartial : null,
    fitCalculatedAt: fs ? fs.calculatedAt : null,
    predictionStatus,
    hiredById: input.hiredById,
  };
}

export const hirePredictionService = {
  /**
   * Read the candidate's current FIT (if any) and persist an immutable snapshot.
   * Called from inside convertToEmployee's $transaction (write goes on `tx`).
   * The FitScore read runs as a standalone tenantDb op (RLS-scoped, separate
   * pool connection) — safe: fit_scores is not written by the hire tx, so no
   * lock contention, and the snapshot is inherently a point-in-time capture.
   */
  async captureAtHire(
    tx: Prisma.TransactionClient,
    params: Omit<BuildHirePredictionInput, 'fitScore'>,
  ): Promise<void> {
    const fitScore = await fitEngineRepository.getFullFitScoreForSnapshot(
      params.organizationId,
      params.candidateId,
      params.vacancyId,
    );
    const snapshot = buildHirePredictionSnapshot({ ...params, fitScore });
    await hirePredictionRepository.createHirePrediction(tx, snapshot);
  },
};
```
