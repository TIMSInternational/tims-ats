## Global constraints (LOCKED decisions — bind every slice)
- **Competencies (decision B):** a FRESH config set of exactly 6 keys in `packages/shared`
  (`EVAL360_COMPETENCIES = ['leadership','communication','collaboration','execution','adaptability','integrity']`,
  `as const`, exported type `Eval360Competency`). Rating scale = Int **1–5** (zod `.int().min(1).max(5)`). No DB Competency table.
- **Anonymity (decision C) — the crux:**
  - `self` → shown (it's the subject's own rating).
  - `manager` → shown ATTRIBUTED (manager feedback is non-anonymous; there is normally 1 manager).
  - `peer` and `direct_report` → aggregated per relationship bucket, shown ONLY when that bucket has **≥3
    submitted raters**; below 3 → suppressed (`{ suppressed:true, average:null, raterCount:null }`). Never return a
    single rater's raw row for peer/direct_report. Implement `suppressBelowMin3` in a NEW `evaluation360` aggregate
    helper — DO NOT modify the shared `aggregate.ts`/`MIN_AGGREGATE_SIZE=5`.
  - Anti-differencing: for suppressed peer/report buckets, do NOT also disclose that bucket's exact submitted
    count elsewhere in the report (mirror the `aggregateGroups` guard). Comments (free text) for peer/report are
    aggregated into the bucket ONLY when the bucket is not suppressed; never attributed to a rater.
  - The report is returned ONLY when `cycle.status === 'published'`; otherwise NOT_FOUND/empty.
- **Org isolation & IDOR:** every query/mutation filters by `ctx.user.organizationId`; every by-id mutation uses
  `assertScoped('raterAssignment', …)` or an org-scoped fetch-then-check. A rater submits ONLY to their own
  assignment (`raterUserId === ctx.user.id`); a subject reads ONLY their own report (`subjectUserId === ctx.user.id`).
- **Status transitions atomic:** cycle transitions (`draft→open→closed→published`) via guarded `updateMany`
  (where-clause includes the expected current status; `count===0` ⇒ CONFLICT). No illegal transitions
  (e.g. publish requires `closed`; open requires `draft`).
- **RLS:** every new table gets its OWN `ENABLE + FORCE ROW LEVEL SECURITY + CREATE POLICY tenant_isolation` block
  in the same migration (template = `20260713120000_add_hire_predictions/migration.sql`).
- **TS strict, no `any`; explicit Prisma `select`; zod at every boundary; strings bounded** (`name ≤200`,
  `comment ≤5000`); **no hardcoded UI strings** (es+en keys, parity). **Gate every slice:**
  `cd packages/db && npx prisma generate --schema=prisma/schema` → `pnpm --filter @tims/api exec tsc --noEmit` →
  `cd apps/web && npx tsc --noEmit` → `npx vitest run` (FULL suite).

**Tests (dmmf/array, no live DB):** `tests/db/evaluation360-schema.test.ts` (3 models + enums + unique keys present);
`tests/access/evaluation360-grants.test.ts` (`MODULES` includes `evaluation360`; MATRIX has the exact per-role grants);
extend `permission-vocabulary.test.ts` count if it hardcodes one.
**Schema (exact):**
```prisma
enum ReviewCycleStatus { draft open closed published }
enum RaterRelationship { self manager peer direct_report }
enum RaterAssignmentStatus { pending submitted }

model ReviewCycle {
  id String @id @default(uuid()) @db.Uuid
  organizationId String @map("organization_id") @db.Uuid
  name String
  status ReviewCycleStatus @default(draft)
  opensAt DateTime? @map("opens_at")
  closesAt DateTime? @map("closes_at")
  publishedAt DateTime? @map("published_at")
  createdById String @map("created_by_id") @db.Uuid
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")
  createdBy User @relation("ReviewCycleCreatedBy", fields: [createdById], references: [id])
  assignments RaterAssignment[]
  @@index([organizationId])
  @@map("review_cycles")
}
model RaterAssignment {
  id String @id @default(uuid()) @db.Uuid
  organizationId String @map("organization_id") @db.Uuid
  cycleId String @map("cycle_id") @db.Uuid
  subjectUserId String @map("subject_user_id") @db.Uuid
  raterUserId String @map("rater_user_id") @db.Uuid
  relationship RaterRelationship
  status RaterAssignmentStatus @default(pending)
  submittedAt DateTime? @map("submitted_at")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")
  cycle ReviewCycle @relation(fields: [cycleId], references: [id], onDelete: Cascade)
  subject User @relation("RaterAssignmentSubject", fields: [subjectUserId], references: [id])
  rater User @relation("RaterAssignmentRater", fields: [raterUserId], references: [id])
  responses RaterResponse[]
  @@unique([cycleId, subjectUserId, raterUserId])
  @@index([organizationId])
  @@index([cycleId])
  @@index([raterUserId])
  @@index([subjectUserId])
  @@map("rater_assignments")
}
model RaterResponse {
  id String @id @default(uuid()) @db.Uuid
  organizationId String @map("organization_id") @db.Uuid
  assignmentId String @map("assignment_id") @db.Uuid
  competencyKey String @map("competency_key")
  rating Int
  comment String?
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")
  assignment RaterAssignment @relation(fields: [assignmentId], references: [id], onDelete: Cascade)
  @@unique([assignmentId, competencyKey])
  @@index([organizationId])
  @@index([assignmentId])
  @@map("rater_responses")
}
```
Add the matching back-relations on `User`: `reviewCyclesCreated ReviewCycle[] @relation("ReviewCycleCreatedBy")`,

Migration = `CREATE TYPE` × 3 enums + `CREATE TABLE` × 3 + indexes + FKs + **an RLS block per table** (ENABLE/FORCE/

## Slice 2 — Admin cycle CRUD + rater assignment (`organization` scope)
Router `packages/api/src/routers/evaluation360.ts` + `services/evaluation360.service.ts` +
`repositories/evaluation360.repository.ts`; mount in `root.ts` (`evaluation360: evaluation360Router`).
Procedures (all `permissionProcedure('evaluation360', <action>)`):
- `createCycle({ name })` → create draft (create action).
- `openCycle/closeCycle/publishCycle({ cycleId })` → atomic guarded transitions (update action): open requires
  `draft`, close requires `open`, publish requires `closed`; set `opensAt/closesAt/publishedAt`. `count===0`⇒CONFLICT.
- `assignRaters({ cycleId, assignments: [{ subjectUserId, raterUserId, relationship }] (≤500) })` → create action;
  validate cycle is `draft`/`open`; transactional `createMany` with skipDuplicates on the unique key; validate all
  user ids belong to the org (repository check) — reject cross-org ids.
- `listCycles()` / `getCycleProgress({ cycleId })` → read action; progress = counts submitted/total per relationship.
Tests: service unit (transition guards, CONFLICT, org-id validation, dedup) + repo (org-scoped selects). Commit `feat(360): Slice 2 — admin cycle CRUD + rater assignment`.

## Slice 3 — Rater task list + submission (assigned/own scope)
Register `raterAssignment` in `access/entity-policies.ts` (`ScopedEntity` union + `ENTITIES` + `scopeWhereFor`
switch: rater anchor `{ raterUserId: userId }`) and in `access/scoped-probe.ts` (`DELEGATES` + `NOT_FOUND_MESSAGES`).
Procedures:
- `myRaterTasks()` → `permissionProcedure('evaluation360','read')`, returns pending assignments where
  `raterUserId = ctx.user.id` AND cycle status = `open` (with subject display name + relationship + competency list).
- `submitRatings({ assignmentId, ratings: [{ competencyKey ∈ EVAL360_COMPETENCIES, rating 1–5, comment? ≤5000 }] })`
  → `permissionProcedure('evaluation360','update')` + `assertScoped('raterAssignment', assignmentId, …)`; the
  assignment MUST belong to `ctx.user.id` as rater AND cycle status = `open`; require all 6 competencies present
  (bounded, no dup keys — enforce via the `@@unique`); transactional: upsert responses + flip assignment
  status→submitted + set submittedAt. Re-submit to an already-submitted assignment ⇒ CONFLICT (atomic guard).
Tests: service (own-only enforcement via scoped probe mock, full-competency requirement, CONFLICT on re-submit, cycle-must-be-open) + repo. Commit `feat(360): Slice 3 — rater task list + submission`.

## Slice 4 — Aggregation + anonymized subject report (the anonymity crux)
New `packages/api/src/services/evaluation360-aggregate.ts` (pure) + `suppressBelowMin3` helper. `myReport({ cycleId })`
→ `permissionProcedure('evaluation360','read')`, subject = `ctx.user.id`:
- Only if cycle.status = `published` AND an assignment exists with `subjectUserId = ctx.user.id`; else NOT_FOUND.
- Aggregate submitted responses for that subject+cycle, grouped by `relationship` then `competencyKey`:
  - `self`: raw averages shown (single self assignment).
  - `manager`: averages shown, attributed (relationship label only — no rater identity in the payload regardless).
  - `peer`, `direct_report`: per-competency average over submitted raters of that relationship; INCLUDE only if the
    bucket's submitted rater count `≥ 3`; else `{ suppressed:true, average:null }` and omit its comments + exact count.
  - Never include `raterUserId`/rater identity anywhere in the report payload.
- Pure aggregation is fully unit-tested with EXPLICIT anonymity cases: 2-peer bucket → suppressed; 3-peer → shown;
  self always shown; manager shown; suppressed bucket exposes no count/comments; mixed buckets independent.
Tests: `tests/evaluation360/evaluation360-aggregate.test.ts` (the anonymity truth table — the most important tests in the sprint) + service (published-gate, subject-only). Commit `feat(360): Slice 4 — aggregation + anonymized report`.

## Self-review / anonymity checklist
Every layer filters by org; rater submits own-only; subject reads own-only; peer/report < 3 ⇒ suppressed with no
count/comment leak; self/manager shown; report gated on `published`; RLS on all 3 tables; no `any`; no hardcoded
strings; competency set is the fixed 6; transitions atomic. The report payload NEVER contains a rater identity.
