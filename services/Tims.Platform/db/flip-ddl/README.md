# Flip DDL — executable definitions for ownership-flipped tables

Generated by `scripts/db/extract-table-ddl.mjs` from the committed production baseline
(`packages/db/baseline/prod-public-schema.sql`). **Do not edit these files by hand** — a test asserts they
match what the generator produces, so a manual edit fails CI.

```bash
node scripts/db/extract-table-ddl.mjs --out services/Tims.Platform/db/flip-ddl/<name>.sql <table>...
```

## Why they exist

Ownership-flip runbook **§0 P8**: deleting a Prisma model can remove the only executable definition of a
table from this repository. `prisma db push` is the documented post-clone bootstrap step
(`CLAUDE.md:32`, `README.md`), so without these files a freshly bootstrapped dev database simply would not
have the table, and seeds referencing it would fail.

Measured on `main` after the first flip: of 101 Prisma-mapped tables, only **17** have a `CREATE TABLE`
anywhere in `packages/db/prisma/{migrations,manual}`. The other 84 were created by `prisma db push` and
exist as DDL nowhere. See **#128**.

`access_reviews` (flip #1) did not need this — it had a real migration file, which is part of why it was
the right pilot.

## ⚠ `pnpm push` on an EXISTING local DB will DROP a flipped table

Because the Prisma model is gone, `prisma db push` sees the live table as something not in the schema and
wants to remove it. On a **fresh** database that is invisible (the table is simply never created — which is
why these files exist). On an **existing** local database that already has the table, `db push` will
propose dropping it and, with `--accept-data-loss`, will.

That is expected and is not a production risk: `pnpm push` / `pnpm migrate` route through
`scripts/db/guard-prod-ddl.sh`, which refuses a non-local host; Prisma Migrate is formally unused against
prod (no `_prisma_migrations` table there, verified #115); and `/gate` check 16 would catch it if anything
did reach prod. It IS a local-dev footgun, so after a `pnpm push` that follows an ownership flip:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f services/Tims.Platform/db/flip-ddl/<name>.sql
cd packages/db && npx tsx prisma/seed.ts && npx tsx prisma/seed-users.ts && npx tsx prisma/seed-demo.ts
```

(That seed order is required — `seed-demo.ts` bails out without the org and users the first two create.)

Raised by the tier-2 cross-model reviewer against #131 as a claimed prod/CI risk. The CI half was wrong —
nothing runs `prisma migrate deploy`, and `pnpm migrate` is the guarded local-only wrapper — but the
local-dev half is real, and it applies to every flipped table, including `access_reviews` from flip #1.

## ⚠ Never apply these to production

The tables already exist in prod. These are **bootstrap / dev-parity** artifacts. Production DDL goes
through [`docs/architecture/ddl-governance.md`](../../../../docs/architecture/ddl-governance.md), and
`/gate` check 16 is what proves nothing here was applied to prod.

## Properties

- **Idempotent.** `CREATE TABLE/SEQUENCE/INDEX IF NOT EXISTS`; constraints guarded on `pg_constraint`
  (Postgres has no `ADD CONSTRAINT IF NOT EXISTS`); enums guarded on `pg_type`; `DROP POLICY IF EXISTS`
  before `CREATE POLICY`; triggers dropped before creation. Verified by applying three times in a row.
- **Atomic.** One `BEGIN … COMMIT`, so a failed apply leaves nothing behind.
- **Faithful to production, not to the migrations.** The RLS policy is the one `pg_catalog` actually has.
  #111 proved those two differ, and the migration source is the one you must not trust.
- **Grants are role-guarded**, since `app_tenant` may not exist on a fresh database.
- **Foreign keys last**, so a multi-table file applies regardless of table order.
- **No `OWNER TO`** — it would fail wherever the local superuser is not `postgres`, and ownership is not
  what dev parity needs.

## Applying to a dev database

FK parents outside the extraction must exist first; the generator prints exactly which ones on stderr.
In practice they are Prisma-owned and `prisma db push` has already created them, so the order is:

```bash
cd packages/db && npx prisma db push --schema=prisma/schema   # creates the Prisma-owned tables
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f services/Tims.Platform/db/flip-ddl/<name>.sql
```
